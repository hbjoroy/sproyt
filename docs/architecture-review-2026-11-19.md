# Oppfølgjande arkitekturrevisjon 19. november 2026

Den første revisjonen 5. november peika på kostnaden ved små endringar, delt databasekapasitet og uklare grenser mellom chat og tilleggsfunksjonane. Denne gjennomgangen følgjer leveransane under [#345](https://github.com/hbjoroy/sproyt/issues/345). Godkjenninga av beta-drifta 7. november står ved lag. Status for utrulling kan endre seg etter revisjonen og blir ført i GitOps.

| Område | Resultat og bevis | Ansvar og tidspunkt for ny vurdering |
|---|---|---|
| Iterasjon og tryggleik | Risikobasert utval, målingar for små endringar og vurdering av RSA-unntaket er leverte. [CI-policy](ci-iteration-strategy.md) · [Tryggleiksunntak](security-exceptions.md) | Vedlikehaldar oppdaterer testkartet ved endra modulgrenser. Tryggleiksansvarleg følgjer revisjonsvilkåra for unntaket. |
| Chat og ressursbruk | Mål for kvittert sending er 99 % innan 750 ms, for reconnect 99 % innan 5 s. Dei isolerte prøvene nådde måla ved 160 sendingar/s og braut dei ved 320/s. Behald felles pool og chataktør. [Lastprøver og ressursrekneskap](database-capacity-assessment-2026-11-10.md) | Chat og drift måler på nytt ved vesentleg trafikkvekst eller vedvarande kø eller timeout. Infrastruktur og eigarane av delte tenester må fastsetje samla tak og reserve før oppskalering. [#353](https://github.com/hbjoroy/sproyt/issues/353) |
| Utrulling og feilisolasjon | Under ei produksjonsøkt var berre 0–1 ordinære PostgreSQL-plassar ledige i tre punktmålingar. Eit nytt push-arbeidarmiljø ville konkurrere om den same ramma. [Målingar](https://github.com/hbjoroy/sproyt/pull/411) · [Rolleavgjerd og kontroll av push-kvitteringar](https://github.com/hbjoroy/sproyt/pull/413) | Drift vurderer kvar utrullingsfase med hookar og terminerande poddar. Plattform og varsling vurderer eiga push-rolle ved målt kø, isolasjonsbehov eller tildelt kapasitet. Produkteigar eig eventuell aksept av utsetjinga. [#354](https://github.com/hbjoroy/sproyt/issues/354) |
| Eigarar og kontraktar | Kontodata eig eksportformat, tidsfrist og adgangskontroll for samtidige eksportar. Identitet eig autentisering og profiloppdatering. Dataeigarane eig bidraga sine i same databasesnapshot. [Modulutskiljing og ansvarskart](https://github.com/hbjoroy/sproyt/pull/417) | Kontodata og adaptereigarane verifiserer wireformat, eitt snapshot, avbroten klient og samtidige brukarar ved nye eksportbidrag. [#355](https://github.com/hbjoroy/sproyt/issues/355) |
| Personvern og misbruk | Register, operatørveg og skrivebordsøving dekkjer sletting med ein aktiv jobb, eldre backup og feilaktig sperring. [Operatørprosedyre](privacy-and-abuse-operations.md) | Før breiare bruk skal identitet/drift prøve kontosletting, drift prøve ny handheving etter restore og produkt/personvern vedta ansvar, fristar og privat rapporteringsveg. [#414](https://github.com/hbjoroy/sproyt/issues/414) · [#415](https://github.com/hbjoroy/sproyt/issues/415) · [#416](https://github.com/hbjoroy/sproyt/issues/416) |

Neste ordinære revisjon er seinast 5. februar 2027. Vesentleg trafikkvekst, endra databruk eller ei kapasitets- eller utrullingshending utløyser tidlegare vurdering. Samla ressursbudsjett, personvernvedtak og eventuell godkjenning av avvik står framleis hjå eigarane.
